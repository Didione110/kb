## 问题现象

如何停用OA系统不使用的功能插件

## 问题原因

系统每次启动都超过10分钟，是否可以通过停用用户不需要的插件来加速启动？

## 解决方案

常规方法：登录系统管理员，访问“系统模块管理”菜单，停用不必要的插件。停用后需要重启OA服务生效。

非常规方法：数据库操作停用不必要的插件
数据库有一个字段用于控制哪些插件即使在加密狗中存在，也不能启动，可以基于此原理去做自定义停用。
首先，要知道用户有哪些插件，启动OA系统后，找到服务器上logs\_sy/ctp.log日志，打开看到被启用的插件：
随后，就是根据插件名称定向停用不必要的插件，操作方式如下：
管理员连接OA数据库，通过如下SQL查询哪些插件被停用：
SELECT \* from ctp\_config where CONFIG\_ITEM='disabled\_ids';
随后就是依葫芦画瓢，根据ctp.log中的插件清单，停用不必要的参数：

-- 如下语句表示把rss,ai,aicloud,docComparison这4个插件都停用，想停什么就以半角符号分割增加插件名即可
update ctp\_config set CONFIG\_VALUE='rss,ai,aicloud,docComparison' where CONFIG\_ITEM='disabled\_ids';

风险：禁用某个插件可能会导致系统无法启动，故需要项目上小心尝试，一点点禁用，如果发现不可使用则不要禁用该插件。
