# 【CAP4-触发预写】设置了触发预写且流程表设置了校验规则，但是底表仍然超预算。
当前预写的常见业务设置如下
1.流程流程表触发更新底表，并且配置预写
映射设置：流程表.报销金额 + 底表.已用金额 = 底表.已用金额
预写设置：底表.在途金额 = 底表.已用金额
2.流程表设置关联关系，将底表的已用金额，总预算金额，可用金额等字段关联到流程表
3.配置校验规则 总预算金 &gt;= 已用金额 + 报销金额 或 可用金额 &gt;= 报销金额

上面的设置中，流程表中已经加了校验规则，但是仍然会出现底表超过总预算或者可用金额为负数的情况

## 问题现象

【CAP4-触发预写】设置了触发预写且流程表设置了校验规则，但是底表仍然超预算。
当前预写的常见业务设置如下
1.流程流程表触发更新底表，并且配置预写
映射设置：流程表.报销金额 + 底表.已用金额 = 底表.已用金额
预写设置：底表.在途金额 = 底表.已用金额
2.流程表设置关联关系，将底表的已用金额，总预算金额，可用金额等字段关联到流程表
3.配置校验规则 总预算金 &gt;= 已用金额 + 报销金额 或 可用金额 &gt;= 报销金额

上面的设置中，流程表中已经加了校验规则，但是仍然会出现底表超过总预算或者可用金额为负数的情况

## 问题原因

上面的设置中，只对流程表做了校验规则限制，但是流程其实时可以同时发起的
如果A发起流程打开表单，关联底表数据剩余可用1000到流程表
此时B也发起流程打开表，并且也从底表关联了剩余可用1000，
那么A报销900，发送流程，B也报销900并发送流程，
此时他们各自的流程表单的校验规则都是可以通过的，但是实际总共却报销了1800，从而导致底表可用金额为负数

## 解决方案

正确的预写设置中，如果要避免超预算的问题，必须在底表也设置校验规则，
底表设置了校验规则，就算两条流程同时发起，也只会有先发送的流程成功，后发送的流程发送回失败。
